## 1. XXD

Der Befehl `xxd` sorgt dafür das eingegebene Normale Buchstaben in Asc Code angezeigt werden.

bsp:
```sh
echo "a" | xxd
00000000: 610a                                     a.
```

### Die Optionen `-n -r -p` 

-n sorgt dafür das echo keinen Zeilenumbruch mehr dranhängt.

-p sorgt dafür das xxd nur mehr der Ascii Code angezeigt wird und nicht mehr die Stelle wo es liegt in Hex und was es in Normalen Zeichen ist.

-r sorgt dafür das xxd rückwärts funktionert also aus Ascci normale Zeichen macht.


bsp mit Emojis:

```sh
echo -n "😃" | xxd -p
f09f9883
```


```sh
echo -n "f09f9883" | xxd -r -p
😃
```

### Aufgabe: Hex Dump

**Aufgabenstellung:** Zeige mit `xxd` und `hexdump` eine binäre Ausgabe an (`-b` Option).

**Lösung:**

Mit `xxd -b` wird jedes Byte als 8 Einsen/Nullen (Binär) angezeigt, mit `hexdump -b` als Oktalzahl. Der Buchstabe `A` hat den Wert `65` – in Binär `01000001`, in Oktal `101`.

```sh
echo -n "A" | xxd -b
00000000: 01000001                                               A

echo -n "A" | hexdump -b
0000000 101
0000001
```

### Aufgabe: Octet

**Aufgabenstellung:** Was bedeutet „Octet" und warum wird es verwendet?

**Lösung:**

Ein **Octet** ist immer genau 8 Bit. Früher hatten manche Systeme Bytes mit unterschiedlicher Größe (z. B. 6 oder 9 Bit), daher brauchte man einen eindeutigen Begriff. Heute ist Octet vor allem in Netzwerkprotokollen wie IPv6 noch gebräuchlich.

### Aufgabe: xxd Option `-E`

**Aufgabenstellung:** Was bewirkt die Option `-E` bei `xxd`?

**Lösung:**

Mit `-E` zeigt `xxd` die Zeichen rechts nicht in ASCII, sondern in **EBCDIC** an – einem alten Zeichensatz von IBM für Großrechner. Die Hex-Werte bleiben gleich, nur die Darstellung rechts ändert sich.

```sh
echo -n "Hello" | xxd -E
00000000: 4865 6c6c 6f                             &#$%%
```

### Aufgabe: Printf und `%.8x`

**Aufgabenstellung:** Erkläre `printf "%.8x"` und wie man einen Hex-Wert zurück in Dezimal umrechnet.

**Lösung:**

`printf "%.8x"` wandelt eine Dezimalzahl in Hex um und füllt auf 8 Stellen auf. Mit `$((16#...))` geht die Umrechnung zurück von Hex nach Dezimal.

```sh
printf "%.8x\n" 65
00000041

echo $((16#41))
65
```

### Aufgabe: Windows Editor – UTF-8 vs. ANSI

**Aufgabenstellung:** Was ist der Unterschied zwischen UTF-8 und ANSI im Windows Editor, und welche Kodierung ist Standard?

**Lösung:**

UTF-8 kann alle Zeichen der Welt speichern, ANSI nur eine begrenzte Auswahl je nach Region. Seit Windows 10 ist UTF-8 der Standard im Editor – bei älteren Versionen war es ANSI, was oft zu kaputten Sonderzeichen geführt hat.

### Aufgabe: Hexdump Analyse – ANSI vs. UTF-8

**Aufgabenstellung:** Zeige die Kodierung von `Ö`, `ß` und `€` in ANSI (Windows-1252) und UTF-8 per Hexdump.

**Lösung:**

In ANSI braucht jedes Zeichen nur 1 Byte, aber die Werte funktionieren nur in der jeweiligen Region. UTF-8 braucht mehr Bytes, dafür funktioniert es überall gleich.

| Zeichen | ANSI | UTF-8 |
|---------|------|-------|
| Ö | `d6` | `c396` |
| ß | `df` | `c39f` |
| € | `80` | `e282ac` |

```sh
echo -n "€" | xxd -p
e282ac
```

### Aufgabe: Zeilenumbrüche – Windows vs. Linux

**Aufgabenstellung:** Was ist der Unterschied zwischen Zeilenumbrüchen unter Windows und Linux?

**Lösung:**

Linux beendet eine Zeile mit einem einzigen Zeichen (`0a`), Windows mit zwei (`0d0a`). Das kann Probleme machen, wenn man eine Windows-Datei unter Linux öffnet – dann steht ein `^M` am Zeilenende.

| System | Hex |
|--------|-----|
| Linux | `0a` |
| Windows | `0d0a` |

```sh
printf "Zeile1\r\nZeile2" | xxd -p
5a65696c65310d0a5a65696c6532
```
